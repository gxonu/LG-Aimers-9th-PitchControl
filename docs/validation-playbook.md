# 검증 규율 — 로컬 지표에 속지 않는 법

> 본 대회에서 **직접 측정한 수치만** 사용했다. 측정하지 않은 항목은 쓰지 않았다.

---

## 0. 한 줄 명제

**로컬 raw 점수 = 판별력 + 레벨오차.**

제출 시 세그먼트별 고정 상수 `b`가 레벨을 어차피 흡수한다.
따라서 **레벨에서 온 로컬 이득은 리더보드로 전이되지 않는다.**

이건 이 대회 특유의 함정이 아니라 **"세그먼트별 사후 상수 보정이 허용되는 모든 확률 예측 과제"의 구조적 성질**이다.
로컬 지표 안에 그 상수가 할 일이 섞여 있으면, 그 부분은 언제나 신기루다.

---

## 1. 판정 규칙

예측의 평균을 실제 평균에 강제로 맞춘 뒤 채점한 값을 `mc`(mean-corrected)라 하자.
이는 정답을 읽으므로 **오라클 지표이고 제출 경로에 절대 들어가면 안 된다.** 오직 진단용이다.

**규칙 1 — mc/raw 이득비**

| 비율 | 해석 |
|---|---|
| ≥ 0.8 | 진짜 판별력 → LB 전이 기대 |
| ≤ 0.2 | 레벨 재조정 → LB 미전이 |
| 0.3 ~ 0.7 | 비율 하나로 판정 금지, 세그먼트별로 분해 |

⚠️ 0.8 / 0.2는 교정된 상수가 아니라 **관측 4점에서 고른 휴리스틱 절단점**이다.

🚧 **분모 붕괴 가드**: `|Δraw|`가 시드 산포보다 작으면 비율은 무의미하다.
(예: Δraw +0.3 / Δmc +2.0 → 비율 6.7이 나오지만 아무 뜻도 없다.) 이 경우 **Δmc 절대값으로 판정한다.**

**규칙 2 — 소수 세그먼트의 raw 이득은 단독 신뢰 금지**

전역 mc는 소수 세그먼트의 평균오차를 판별력으로 **오계상**한다. 반드시 세그먼트별로 재확인한다.

**규칙 3 — "시너지" 주장 전에 시드 산포부터 잰다**

단순합 초과분이 시드 산포와 동급이면 증거가 없는 것이다.

### 실측 근거

| 관측 | 수치 |
|---|---|
| 2024 **F** 세그먼트 raw ↔ mc 격차 | 423.6 vs 588.0 = **+164.4** — 레벨만 밀어도 세 자릿수가 움직인다 |
| 2024 **R** 세그먼트 raw ↔ mc 격차 | 895.5 vs 904.8 = **+9.2** — 레벨 장난이 안 통함, **R이 정직한 신호** |
| 낮은 쪽 실측 | 겉보기 raw **+14.5** → mean-corrected **+3.0**, 비율 **0.21** → 이득의 80%가 레벨 |
| 높은 쪽 실측 | 두 독립 실험에서 비율 **0.83 / 0.816** 교차 일치 |

## 2. 실패 사례 — 무엇을 잘못 읽었나

하루 동안 전략 판단이 **다섯 번 뒤집혔다.** 그동안 모델 성능이 바뀐 적은 **한 번도 없다.**

### ① 유령 수치

두 실험이 서로 다른 설정으로 저장돼 있었는데(한쪽은 `pooled/free/ID-on`, 다른 쪽은 `forward/anchored/ID-off`)
이를 나란히 비교해 **"백본이 −107"** 이라는 수치를 만들어냈다.
그 값은 **어떤 metrics 파일에도 존재하지 않았다.**

> **교훈**: 비교 전에 두 런의 config가 *한 축만* 다른지 확인한다. 세 축이 동시에 다르면 ablation이 아니다.

### ② 평가 폴드 누출 — 부호가 반대로 나온 사례

`--gate-mode pooled` 옵션이 gate뿐 아니라 **stack 적합에도** 평가 연도를 포함시키고 있었다.
`anchored` 모드는 main 계수가 1.0으로 **고정**인데도 stack 점수가 +59 올랐다 —
intercept와 hazard 계수가 평가 연도의 정답을 보고 맞춰졌다는 직접 증거다.

같은 후보에 대해 두 프로토콜이 **정반대 예측**을 냈다:

| 프로토콜 | 로컬 Δ | 예측 |
|---|---|---|
| `pooled` (누출) | +4.4 | 기존 모델보다 **높다** |
| `forward` (정직) | −142 | 기존 모델보다 **낮다** |

**실측 LB: −27.6.** `forward`가 옳았고 `pooled`는 **부호를 틀렸다.**

이후 인자를 만들어 두 효과를 분리하니, 평가 연도 자기포함 효과 단독으로 **+382**였다.
584개 리프짜리 모델의 in-fold 점프 — 명백한 암기 시그니처다.

> **교훈**: 평가 폴드를 적합에 포함한 수치는 **크기가 아니라 방향조차** 못 맞힌다.

### ③ 컬럼 오독 — 하루 3회 반복

metrics에 `skill`(raw), `raw_fwd`, `oracle_mc`, `oracle_mc_segment`, `affine_ceiling`이 함께 있는데
**`skill`이라는 키 이름이 "raw"로 안 보여서** 서로 다른 사람이 세 번 혼동했다.
한 번은 이득을 40% 축소 인용했고, 한 번은 전이율 계산의 분모를 틀렸다.

### ④ 섹션 오독

로그 텍스트에서 첫 번째 `2024` 줄을 stack 값으로 읽었는데, 실제로는 **개별 채널 값**이었다.
네 조합이 전부 같은 값으로 보여 "설정이 반영 안 된다"는 엉뚱한 진단까지 갔다.

### ⑤ 산문으로 옮겨 적다 틀리기

코드는 `[i for i, b in enumerate(TABLE) if b & 1]`로 올바르게 계산하고 있었는데,
그 결과를 **설명문에 수기로 옮기면서** 인덱스를 잘못 적었다.
이를 본 동료가 "코드가 틀렸으니 중단·재시작하라"고 판단했다 — 40~80분을 날릴 뻔했다.

> **교훈**: 구현 확인은 **산문이 아니라 코드 라인 + 실제 평가 출력**으로 한다.

## 3. 체크리스트 — 새 결과를 보고할 때마다

- [ ] 이 수치가 나온 run이 **실재하는가** — metrics 파일을 직접 열어 확인했는가
- [ ] 비교 대상 두 런이 **한 축만** 다른가
- [ ] **컬럼명을 병기**했는가 (`skill` / `raw_fwd` / `mc` / `mc_segment`)
- [ ] 적합에 **평가 폴드가 들어가지 않았는가**
- [ ] mc/raw 이득비를 냈는가 — 분모가 시드 산포보다 큰가
- [ ] 소수 세그먼트 이득이면 **세그먼트별로** 재확인했는가
- [ ] 전이율을 **점추정하지 않았는가** — 관측 기울기가 0.19 ~ 0.60으로 3배 흩어져 있다

## 4. 사전등록 (pre-registration)

게이트·선택 지표·중단 기준을 **실행 전에 파일로 동결**하고, 결과를 본 뒤에는 옮기지 않는다.

```
1. 선택 폴드와 held-out 폴드를 먼저 고정한다
2. 게이트 임계값을 숫자로 적는다
3. 중단 기준(예산 소진 시 어떻게 할지)을 적는다
4. 실행한다
5. 결과가 게이트를 못 넘으면 — 넘지 못한 것이다
```

실제로 이 규율 덕에 여러 실험이 **NO-GO로 기각되어 제출 슬롯을 아꼈다.**
하루 5회뿐인 제출에서 이는 직접적인 이득이다.

**수정이 필요할 때**: 결과를 보기 *전에* 발견한 물리적/구조적 불가능만 Amendment로 고친다.
사유·시점·증거를 함께 기록해, 나중에 "결과를 보고 고친 게 아니다"가 문서로 남게 한다.

예시 — 실제로 있었던 두 건:
- 게이트가 `batch == singleton` **bitwise 동일**을 요구했는데, GPU 부동소수점에서는 원리적으로 불가능했다.
  실측 오차가 정확히 `2⁻²³`(float32 기계 엡실론)이었다. → `< 1e-6` + **배치 뒤섞기 검사 추가**로 수정.
  기준을 *낮춘 게 아니라 높인* 것이다. 배치 구성을 바꿔도 예측이 불변해야 실제 행 간 누수가 잡힌다.
- 사전등록이 "프레임에 결측이 없다"고 적었으나, 실제로는 162열 중 **20열에 NaN**이 있었다.
  그대로 돌리면 표준화 통계가 전부 NaN이 된다. → 스펙이 이미 명시한 `NaN→0`을 실제로 구현.

## 5. 다음 대회에 가져갈 것

1. **첫날에 프로토콜부터 고정한다.** forward를 기본으로, pooled는 낙관 상한으로만 병기.
   프로토콜 하나가 부호를 뒤집는다는 걸 실측으로 확인했다.
2. **metrics를 구조화된 파일로 남기고, 로그 텍스트는 파싱하지 않는다.**
3. **리더보드가 유일하게 흔들리지 않는 판정자다.** 로컬이 5번 뒤집히는 동안 LB는 한 번도 틀리지 않았다.
   판단이 갈리면 제출해서 끝내는 게 빠르다 — 단, 기대치는 정직한 프로토콜 쪽으로 잡는다.
4. **병렬 세션 상호검증은 실측 효용이 있다.** 하루에 상호 교정이 8회 있었고,
   그중 **리더보드를 잘못 태운 건 0건**이었다. 전부 제출 전에 잡혔다.
