# 방법론 — 파이프라인 상세

## 1. 과제와 지표

투구 **직전**까지 확보 가능한 정보로 그 투구의 제구 성공 여부(0/1)를 확률로 예측한다.

| 항목 | 값 |
|---|---|
| 학습 | 2019–2024, 1,475,092 투구 |
| 평가 | 2025, 245,789 투구 (학습에 없는 미래 시즌) |
| 지표 | Brier Skill Score `max(0, 1e5 × (1 − Brier / r(1−r)))` |
| `r` | 2025 실제 성공률 (비공개) |

### 지표가 강제하는 것

상수 `r`을 모든 행에 찍으면 **정확히 0점**이다. 따라서 순위(AUC)가 아니라 **확률 캘리브레이션**이 1차 레버다.

지표 식에서 LB 1점은 Brier `r(1−r) / 1e5` 만큼에 해당한다. 2025년 성공률을 `r ≈ 0.475`로 두면

```
r(1−r) ≈ 0.2494     ⇒     LB 1점 ≈ Brier 2.49e-6
```

마지막 5일에 오른 101점도 Brier로는 **약 2.5e-4, 전체 오차의 0.1% 수준**이다.
신호가 이만큼 얇다는 사실이 이후 모든 판단(모델 용량, 조기종료, NN 기각)의 근거가 된다.

## 2. 데이터에서 나온 구조적 사실

### 시즌 드리프트

타깃 성공률이 단조 하락한다: 2019 `.565` → 2024 `.486`.
학습 분포와 평가 분포의 레벨이 다르므로, **모델 밖 고정 상수 보정이 반드시 필요하다.**

### `game_type` 레짐 붕괴

| 시즌 | R 성공률 | **F 성공률** |
|---|---|---|
| 2019 | .550 | **.689** |
| 2021 | .513 | **.704** |
| 2022 | .504 | **.709** |
| **2023** | .503 | **.473** ← 절벽 |
| 2024 | .490 | **.459** |

2023년에 F 세그먼트가 **뒤집힌다.** 이 때문에:

- **2022 이전 폴드는 판별력 검증에 쓸 수 없다.** 2022의 높은 점수는 대부분 F/R 분리만으로 얻는 공짜 점수다
- **2023 폴드도 선택 폴드로 부적합하다.** 학습(≤2022)이 전부 구 레짐이라 F 예측이 통째로 무너진다.
  실제로 한 실험에서 2023 폴드의 `skill`이 **0.0**이었는데, 세그먼트별 평균 보정을 하면 **751**로 회복됐다 —
  판별력 문제가 아니라 **R/F 레벨 배분** 문제였다는 뜻
- **2024가 배포 구성과 가장 닮았다.** 2025 학습셋은 신 레짐 2시즌(2023·2024)을 포함하므로,
  fold 2024(신 레짐 1시즌 포함)가 fold 2023(0시즌)보다 배포와 동형이다

> 이 판단은 편의가 아니라 **학습 데이터 구성의 동형성**에 근거한다.

## 3. 최종 파이프라인

```
p = clip( p_anchor + s·r_B1(x) + β·(risk_middle(x) − μ), 0, 1 )
p = sigmoid( logit(p) + b_seg )        # seg ∈ {R, F}
```

### ① Anchor 백본


| 구성 | 사양 |
|---|---|
| 계층 base | 동적 shrinkage — `clip(55 + 220·recent_std + 40/(1+log1p(n)), 50, 180)`, career↔season 신뢰도 가중 결합 |
| 잔차 채널 | CatBoost × 3, recency decay `.55 / .55 / .30`, depth 8, lr .035, l2 12 |
| 실패유형 hazard | CatBoost × 3 (middle / wild / reverse), depth 7, decay `.30` |
| 결합 | 선형 스택 → **depth-3 adaptive gate** (73 iter, l2 30) |

**gate의 1등 입력이 `ensemble_std` / `ensemble_range`** — 즉 세 채널의 **불일치**다.
이 때문에 단일 예측만 내는 백본 위에는 gate를 얹을 수 없고, **3채널 구조가 gate의 전제조건**이다.

### ② B1 잔차 (R행 한정)

독립 계열 백본의 예측을 입력으로 쓰는 얇은 잔차층. 정보원의 *종류*를 바꾸는 축이다.

강도 `s`는 **LB 3점 → 2차 적합 → 정점 예측 → 제출 확인**으로 정했다.

```
s = .15 → 1131.25
s = .35 → 1134.54       2차 적합 예측: s = .50 에서 1135.1
s = .50 → 1135.11  ✅   (s = .65 → 1148.04 계열에서 하락 확인)
```

### ③ rm 잔차 (R행 한정) — 단일 최대 이득

anchor의 선형 스택은 hazard 3종을 입력으로 받지만 **적합 계수의 합이 −0.02**로 사실상 0이다.
그 부품들의 실제 역할은 gate의 입력이지 예측이 아니었다.

`risk_middle` 하나만 떼어 **평균 `μ`를 학습 시점에 동결**하고 음수 계수로 되먹인다:

```
β =  0    → 1135.11
β = −.10  → 1148.13      2차 적합 정점: |β| ≈ 0.14
β = −.15  → 1149.33  ✅  (β = −.20 예측 1147.0, 미제출)
```

**+13.02** — 단일 성분 최대다. *스택이 버렸다고 판단한 자기 부품이, 스택 밖에서는 직교 정보였다.*

> ⚠️ **이 개선은 정직한 로컬 검증을 통과하지 못했다.** 처음 본 양의 신호는 평가 폴드를 엿본 값(fold-peek)이었고,
> 배포 형태 그대로 forward 검증(2023→2024)을 하면 **−15.7**이었다. 로컬 판정이 불가능한 상태에서
> LB 곡선 적합으로 계수를 정해 채택했다. 경위는 [`experiment-log.md` §4](experiment-log.md).

### ④ 캘리브레이션

R / F 세그먼트별 **고정 logit shift**. 학습 시점에 계산한 상수만 사용하며, 테스트 행을 읽지 않는다.

mean shift가 아니라 **logit shift**인 이유는 경계 안전성이다 — 확률이 [0,1]을 벗어나지 않는다.

## 4. 규칙 준수 설계

| 요구 | 구현 |
|---|---|
| 테스트 행 간 정보 사용 금지 | 모든 피처가 행 자신의 컬럼 또는 학습 시점에 동결된 상태만 참조 |
| 행 독립성 | 전 단계가 행 단위 lookup + affine. 배치 통계 사용 없음 |
| 검증 | 격리 환경 전체 실행 + NaN·범위 검사 + `batch == singleton` 차이 **< 1e-9**(부동소수 ULP 수준) + 신규 투수(cold-start) 행 |
| 외부 데이터 금지 | 공식 제공 데이터만 사용 |
| 캘리브레이션 | 학습 시점 고정 상수만. 사후 isotonic 등 미사용 |

### 행 독립성 검증이 실제로 버그를 잡았다

패키징 검증에서 `batch == singleton` 차이가 **2.220e-16**으로 나온 적이 있다.
원인은 선형 스택이 matmul이라 **BLAS가 253,507×4 와 1×4 를 다른 순서로 누적**한 것이었다.
per-row elementwise로 바꿔 **bitwise 0.0**을 달성했다.

규칙 위반은 아니었지만, 이 검사를 규약으로 세워두지 않았다면 발견하지 못했을 종류의 결함이다.

## 6. 하이퍼파라미터에 대한 교훈

**"기본값 = 무난한 선택"은 자동이 아니다.**

CatBoost `max_ctr_complexity`의 기본값은 4다. 1 · 2 · 4를 모두 실측하니
**우리 피처셋에서는 2가 가장 좋았다**(3채널 전부에서 `2 > 4`).

우리는 교차 피처를 명시적으로 투입하고 있어서 **자동 조합 깊이가 같을 이유가 없었다.**
피처셋에 따라 최적값이 달라진다.

한편 이 값을 잘못 낮게(=1) 고정해 뒀던 기간의 손실은 **로컬 +127**로 실측됐다.
원인은 "복잡도를 낮추면 GPU 메모리를 아낀다"는 추정이었는데, 실제로 재보니
complexity 1 / 2 / 4 의 peak 메모리가 **전부 32GB로 동일**했다 — 메모리를 지배하는 건 데이터셋 상주량이었다.

> **교훈**: 측정하지 않은 근거로 하이퍼파라미터를 제약하지 않는다.
